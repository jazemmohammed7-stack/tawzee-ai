## 1. هوية المشروع

**Tawzee AI:** منصة SaaS لإدارة شركات الجملة والتوزيع (السوق اليمنية أولًا). الدورة المستهدفة في MVP: **منتج ← مخزون ← بيع ← فاتورة ← تحصيل ← تقرير**.
التقنيات: Laravel، Blade + Livewire + Tailwind، MySQL/MariaDB مؤقتًا وPostgreSQL هدف مؤجل، Pest/PHPUnit، Modular Monolith، Arabic-first + RTL.
حالة المشروع: **Laravel موجود؛ حالة التنفيذ في TASKS.md.** لا تفترض اكتمال شيء قبل التحقق منه.

## 3. القواعد الحاكمة (مختصرة)

**المعمارية والبرمجة**
- التزم بالحدود في [ARCHITECTURE.md §2](ARCHITECTURE.md#2-هيكل-laravel-المقترح). المنطق ذو الأثر في **Actions**. لا Repository ولا طبقات دون ضرورة موثقة.
- كل جدول مستأجر فيه `company_id` ويستخدم `BelongsToCompany` (استثناء User وCompany محصور بالمصادقة والتسجيل/السياق الداخلي؛ تفاصيل P1-T02 وحدود P1-T05 في ARCHITECTURE §14) ([§5](ARCHITECTURE.md#5-استراتيجية-multi-tenancy)).
- المال أعداد صحيحة `_minor` عبر `Money`، **لا float** ([§6](ARCHITECTURE.md#6-تمثيل-الأموال-دون-float)).
- التغييرات المالية/المخزونية في Transaction واحدة مع Idempotency ([§8](ARCHITECTURE.md#8-database-transactions)، [§9](ARCHITECTURE.md#9-منع-العمليات-المالية-المكررة-idempotency)).
- ملفات صغيرة، أسماء إنجليزية واضحة، `declare(strict_types=1)`، تنسيق Laravel Pint.
- الواجهة عربية RTL؛ النصوص في `lang/ar` لا مضمّنة في القوالب.
- لا حزمة جديدة دون تحقق من توافق الإصدار وسبب واضح وتوثيقها في ARCHITECTURE.md.
- **لا تكتب كود لمهمة غير محددة في [TASKS.md](TASKS.md)** ولا توسّع النطاق خارج MVP ([PROJECT.md §3](PROJECT.md#3-حدود-mvp)).

**الأمان**
- لا وصول عبر الشركات، وتفويض صريح في كل عملية، ولا أسرار في الكود أو Git، ولا تسريب بيانات في السجلات. التفاصيل والتحقق في مهارة [security-quality](.agents/skills/security-quality/SKILL.md).

**الاختبارات**
- كل مهمة تُسلَّم باختباراتها. أي منطق مالي/مخزوني/تفويضي/عزل بلا اختبار = مهمة غير مكتملة.
- لا تدّعِ نجاح اختبار أو أمر لم تنفذه فعلًا. اذكر ما لم تستطع تشغيله.

## 4. طريقة اختيار المهمة وتنفيذها

1. اقرأ «المرحلة الحالية» و«المهمة التالية» في [TASKS.md](TASKS.md).
2. لا تبدأ مهمة قبل اكتمال تبعياتها. إن كانت التبعية ناقصة نفّذها أولًا أو أبلغ.
3. نفّذ **مهمة واحدة** (أو جزءًا صغيرًا منها) في كل دورة، بترتيب: فحص المشروع ← خطة قصيرة ← تنفيذ ← اختبار ← مراجعة ذاتية ← تحديث التقدم ← تقرير.
4. التفاصيل التشغيلية: [SYSTEM_PROMPT.md](SYSTEM_PROMPT.md).

## 6. Definition of Done

المهمة **منتهية** فقط إذا تحقق **كل** ما يلي:

- [ ] معايير قبول المهمة في TASKS.md متحققة، وأي معايير `AC-*` ذات صلة في PROJECT.md.
- [ ] الاختبارات المطلوبة للمهمة مكتوبة وتمر، والاختبارات السابقة لم تنكسر (المخرجات الفعلية مسجّلة).
- [ ] اجتازت قائمة مراجعة [security-quality](.agents/skills/security-quality/SKILL.md) (عزل، تفويض، مال/مخزون إن لزم).
- [ ] أُجري Pint وأي فاحص ثابت مُعتمد في المشروع بلا أخطاء.
- [ ] لا تعارض مع ARCHITECTURE.md، وإن اتُّخذ قرار جديد فقد وُثِّق فيه.
- [ ] الواجهة عربية RTL وتعمل على عرض الجوال (إن وُجدت واجهة).
- [ ] حُدِّثت حالة المهمة في TASKS.md وفق §7.
- [ ] كُتب التقرير النهائي بالتنسيق في SYSTEM_PROMPT.md.

## 7. تحديث تقدم المشروع

- **مصدر الحالة الوحيد:** [TASKS.md](TASKS.md). لا ملفات حالة أخرى.
- الحالات: `Not Started` ← `In Progress` ← `Done` (أو `Blocked` مع السبب).
- `In Progress`: عند البدء. `Done`: **فقط** بعد تحقق Definition of Done، مع إضافة سطر دليل (الأمر الذي شُغّل ونتيجته المختصرة).
- حدّث «المرحلة الحالية» و«المهمة التالية» عند الإكمال. لا تعلّم مهمة `Done` بناءً على النية أو التخمين.
- لا تعدّل معايير القبول لتناسب ما نُفّذ؛ إن لزم تغييرها فاذكر السبب صراحة.

## 8. أوامر ممنوعة دون موافقة صريحة من المستخدم

اطلب موافقة **قبل** تنفيذ أي مما يلي وانتظر ردًّا صريحًا:

- حذف ملفات/مجلدات بالجملة أو أي `rm -rf`، أو `git clean`, `git reset --hard`, `git push --force`, `git checkout .` على تغييرات غير محفوظة.
- `php artisan migrate:fresh`, `migrate:refresh`, `migrate:reset`, `db:wipe`, `db:seed` على قاعدة غير الاختبار المحلية، أو أي `DROP`/`TRUNCATE`/`DELETE` بلا شرط.
- كشف أسرار `.env` أو إدخالها في الكود أو Git ممنوع. فحص وتعديل الإعدادات المحلية اللازمة مسموح ضمن طلب إعداد البيئة المصرح به، دون عرض القيم الحساسة ومع احترام الصلاحيات الفعلية. يلزم الإذن للعمل خارج النطاق أو عند حاجز صلاحيات.
- تثبيت/حذف/ترقية حزم خارج نطاق العمل المصرح به أو نشر/دفع للنسخة البعيدة. تثبيت تبعيات التأسيس المطلوبة مأذون بعد التحقق من التوافق؛ تبقى موافقات الشبكة والبيئة الفعلية واجبة.
- تشغيل أوامر ضد بيئة إنتاج أو بيانات حقيقية.

القواعد الاحتياطية: افحص قبل الحذف، فضّل التغيير الأصغر، ولا تتجاوز حاجزًا أمنيًا للتقدم في مهمة.
